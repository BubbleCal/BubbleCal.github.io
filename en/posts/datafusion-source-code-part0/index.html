DataFusion Source Code, Part 0

A source-reading note on DataFusion's DataFrame execution path, MemoryExec, FilterExec, and how filtering produces new batches.

On this page

DataFusion DataFrame

DataFusion

DataFrame

A DataFrame is a view of the final result dataset. It does not own data and does not execute anything by itself. Query execution starts only when an action method is called.

Using collect() as an example, the execution flow looks like this:

pub async fn collect(self) -> Result<Vec<RecordBatch>> {
    let task_ctx = Arc::new(self.task_ctx());
    let plan = self.create_physical_plan().await?;
    collect(plan, task_ctx).await
}

collect first creates a physical plan and then calls the collect utility to execute it. Internally, that utility calls execute_stream and consumes the stream to collect data:

/// Execute the [ExecutionPlan] and return a single stream of results
pub fn execute_stream(
    plan: Arc<dyn ExecutionPlan>,
    context: Arc<TaskContext>,
) -> Result<SendableRecordBatchStream> {
    match plan.output_partitioning().partition_count() {
        0 => Ok(Box::pin(EmptyRecordBatchStream::new(plan.schema()))),
        1 => plan.execute(0, context),
        _ => {
            // merge into a single partition
            let plan = CoalescePartitionsExec::new(plan.clone());
            // CoalescePartitionsExec must produce a single partition
            assert_eq!(1, plan.output_partitioning().partition_count());
            plan.execute(0, context)
        }
    }
}

If the input has multiple partitions, CoalescePartitionsExec executes the query over each partition concurrently. Therefore, if we want to query several datasets at the same time, one possible approach is to split them into partitions. DataFusion's optimizer can also repartition the original data and split one partition into multiple partitions.

ExecutionPlan

This note mainly looks at MemoryExec and FilterExec.

#### MemoryExec

When querying a MemTable, MemoryExec is the leaf node of the query plan:

fn poll_next(
    mut self: std::pin::Pin<&mut Self>,
    _: &mut Context<'_>,
) -> Poll<Option<Self::Item>> {
    Poll::Ready(if self.index < self.data.len() {
        self.index += 1;
        let batch = &self.data[self.index - 1];

        // return just the columns requested
        let batch = match self.projection.as_ref() {
            Some(columns) => batch.project(columns)?,
            None => batch.clone(),
        };

        Some(Ok(batch))
    } else {
        None
    })
}

Projection may be pushed down to this layer. The logic is simple: select the arrays for the projected columns and build a new RecordBatch containing only those columns.

#### FilterExec

FilterExec filters data from its input:

fn poll_next(
    mut self: Pin<&mut Self>,
    cx: &mut Context<'_>,
) -> Poll<Option<Self::Item>> {
    let poll;
    loop {
        match self.input.poll_next_unpin(cx) {
            Poll::Ready(value) => match value {
                Some(Ok(batch)) => {
                    let timer = self.baseline_metrics.elapsed_compute().timer();
                    let filtered_batch = batch_filter(&batch, &self.predicate)?;
                    // skip entirely filtered batches
                    if filtered_batch.num_rows() == 0 {
                        continue;
                    }
                    timer.done();
                    poll = Poll::Ready(Some(Ok(filtered_batch)));
                    break;
                }
                _ => {
                    poll = Poll::Ready(value);
                    break;
                }
            },
            Poll::Pending => {
                poll = Poll::Pending;
                break;
            }
        }
    }
    self.baseline_metrics.record_poll(poll)
}

The filtering logic roughly iterates over the data in the batch, generates a bitmap, and then uses that bitmap to create a FilterPredicate. FilterPredicate has four strategies:

  • All: select all rows.
  • None: filter out all rows.
  • Slice: generate a set of ranges and select rows covered by those ranges.
  • Index: generate a set of indexes and select rows at those indexes.

When selectivity is greater than 0.8, DataFusion uses the slice strategy. Otherwise it uses the index strategy.

Filtering produces a new batch, and the selected data is copied into that batch.
